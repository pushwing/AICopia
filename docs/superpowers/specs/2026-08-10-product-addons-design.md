# 추가구성상품(애드온) 설계

- 이슈: [#147](https://github.com/pushwing/AICopia/issues/147)
- 작성일: 2026-08-10
- 상태: 승인됨 (구현 대기)

## 배경

상품 상세에서 본품과 함께 쓰는 부속품을 같이 팔 수 있어야 한다. 이슈에 첨부된 화면은 "추가구성상품 — 추가로 구매를 원하시면 선택하세요" 영역에 부속 상품의 이미지·상품명·판매가·옵션 select 를 보여주고, 고른 항목이 아래 목록에 수량과 함께 쌓이는 구조다.

부속품이 **자체 상품명·판매가·옵션**을 갖는다는 것은 곧 일반 상품이라는 뜻이다. 따라서 별도 엔티티를 만들지 않고 기존 `products` 를 연결하는 방식으로 설계한다. 재고 차감, 옵션/SKU, 주문 스냅샷, 환불, 쿠폰 계산 로직을 하나도 새로 만들지 않고 그대로 재사용하기 위해서다.

묶음 정보는 화면 장식이 아니라 **출고 정보**다. 본품과 부속을 같은 박스에 담아 보내야 하므로 장바구니 → 주문 → 엑셀까지 묶음이 유지되어야 한다.

## 목표

1. 관리자가 상품마다 추가구성상품을 연결한다.
2. 고객이 상품 상세에서 추가구성상품을 골라 수량과 함께 본품과 한 번에 담는다.
3. 장바구니 · 주문 상세(회원/관리자) · 주문 엑셀에서 부속이 어느 본품에 딸린 것인지 드러난다.

## 비목표

- 추가구성상품의 추가구성상품(2단계 이상 중첩)은 노출하지 않는다.
- 필수 선택(고르지 않으면 본품을 담을 수 없음) 강제는 넣지 않는다. 모두 선택 사항이다.
- 카테고리 단위 일괄 애드온 규칙은 넣지 않는다.
- 배송추적 일괄 업로드 화면의 컬럼 구성은 바꾸지 않는다.

## 데이터 모델

### 새 테이블 `product_addons`

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `id` | INT UNSIGNED, AI | PK |
| `product_id` | INT UNSIGNED | 본품 |
| `addon_product_id` | INT UNSIGNED | 추가구성상품(기존 `products` 참조) |
| `sort_order` | INT, default 0 | 노출 순서 |
| `created_at` | DATETIME NULL | |

- `uniq_product_addons_pair` UNIQUE (`product_id`, `addon_product_id`)
- `idx_product_addons_product_id` (`product_id`)
- `product_id === addon_product_id` 인 행은 저장 시 거부한다(자기 자신 연결 금지).

### 기존 테이블 변경

- `cart_items.parent_product_id` INT UNSIGNED NULL 추가 — 이 항목이 어느 본품에 딸려 담겼는지.
- `order_items.parent_product_id` INT UNSIGNED NULL 추가 — 주문 시점 스냅샷.

두 컬럼 모두 **삭제·수량·금액 계산에 관여하지 않는다.** 묶어 보여주고 같은 박스로 포장하기 위한 정보다.

## 장바구니

담기는 방식은 **독립 항목**이다. 애드온도 일반 장바구니 항목이 되어 개별로 수량을 바꾸고 지울 수 있다. 본품을 지워도 애드온은 남는다. 화면에서만 본품 아래로 묶어 보여준다.

### 같은 상품이 본품으로도 애드온으로도 담기는 경우

`CartModel::upsert()` 는 `UNIQUE (user_id, product_id, sku_id)` 위에서 `qty = qty + VALUES(qty)` 로 병합한다. 따라서 같은 상품·같은 SKU 는 어느 경로로 담겼든 한 행이 된다. 이때 분류는 **먼저 정해진 값을 유지**한다.

```sql
ON DUPLICATE KEY UPDATE
  qty = qty + VALUES(qty),
  parent_product_id = COALESCE(parent_product_id, VALUES(parent_product_id))
```

표시·포장용 근사치이며, 이 정도면 "어느 본품의 부속인가"를 판단하는 데 충분하다.

### 비회원 세션 장바구니

`session('cart')` 는 `sessionKey(productId, skuId) => qty` 형태의 평면 맵이라 부모를 담을 자리가 없다. 값 구조를 바꾸면 이미 열려 있는 세션이 깨지므로 **병렬 맵**을 둔다.

- `session('cart_addon_of')`: 같은 `sessionKey` → `parentProductId`
- `CartModel::mergeSession()` 이 로그인 시 이 맵을 함께 옮겨 `cart_items.parent_product_id` 로 심는다.

## 담기 경로 — `POST /cart/add-bundle`

본품 1건 + 애드온 N건을 **한 요청**으로 담는 새 엔드포인트를 추가한다. 기존 `POST /cart/add` 의 동작과 시그니처는 그대로 둔다.

기존 엔드포인트를 N번 호출하지 않는 이유: CI4 가 요청마다 CSRF 토큰을 회전시키므로 순차 호출 사이에 응답의 `csrf_hash` 를 다시 심어야 하고, 중간 실패 시 일부만 담기는 상태가 남는다. 한 요청이면 두 문제가 함께 사라진다.

### 요청

```
product_id : int          본품
sku_id     : int|null     본품 SKU
qty        : int          본품 수량
addons     : [{ product_id: int, sku_id: int|null, qty: int }, ...]
```

### 서버 검증

각 애드온에 대해 다음을 확인하고, 통과하지 못한 항목은 **조용히 버리지 않고** 응답 메시지에 담아 돌려준다.

1. `product_addons` 에 (본품, 애드온) 쌍이 실제로 등록돼 있는가 — 임의 상품 주입 차단.
2. 애드온 상품이 `status = 'on_sale'` 이고 삭제되지 않았는가.
3. SKU 를 지정했다면 그 SKU 가 해당 애드온 상품의 것인가.
4. 재고가 있는가. 요청 수량이 재고를 넘으면 재고까지만 담는다(기존 `/cart/add` 와 동일한 규칙).

본품이 유효하지 않으면 애드온도 담지 않는다.

## 관리자 — 상품 폼 안 카드

기존 상품 등록/수정 화면(`app/Views/admin/products/form.php`)의 옵션 카드 아래에 "추가구성상품" 카드를 넣는다. 옵션 카드가 쓰는 방식을 그대로 따른다.

- 상품명으로 검색해 목록에서 골라 추가한다. 이미 추가된 상품과 자기 자신은 후보에서 뺀다.
- 추가된 항목은 썸네일·상품명·판매가와 함께 나열하고, 순서 변경과 삭제를 제공한다.
- 저장은 hidden 필드 `addons_json` 에 실어 상품 저장과 같은 요청으로 보낸다(`options_json` 과 동일한 패턴).
- 서버는 `addons_json` 을 파싱해 `product_addons` 를 전량 교체(delete + insert)한다.

검색 후보를 주는 엔드포인트로 `GET /admin/products/addon-search?q=` 를 추가한다. `auth:admin` 필터 아래 두고, 판매중 상품만 상위 20건으로 제한한다.

## 프론트 — 상품 상세

이슈 화면 구조를 그대로 따른다.

- 본품 정보 아래에 "추가구성상품" 영역. 헤더 문구는 "추가로 구매를 원하시면 선택하세요".
- 항목마다 이미지 · 상품명 · 판매가 · 옵션 select(옵션이 있는 상품만).
- 고르면 하단 선택 목록에 항목이 추가되고 수량 스피너로 조절한다. 총 상품금액에 합산해 보여준다.
- **노출 제외**: 판매중이 아니거나 재고가 0인 애드온, 삭제된 상품.
- 애드온이 하나도 없으면 영역 자체를 렌더하지 않는다.
- `장바구니 담기` · `바로 구매` 모두 `/cart/add-bundle` 로 본품과 선택 애드온을 함께 보낸다.

## 주문

`OrderModel` 이 장바구니에서 주문 항목을 만드는 지점(`order_items` `insertBatch`)에서 `parent_product_id` 를 그대로 옮겨 담는다. 변경 지점은 이 한 곳이다.

- **관리자 주문 상세** — 애드온을 본품 바로 아래에 들여쓰기로 배치하고 `추가구성` 배지를 붙인다. 포장 담당자가 한 박스 단위를 눈으로 구분할 수 있어야 한다.
- **회원 주문 상세** — 같은 방식으로 묶어 표시한다.

정렬 규칙: 본품(= `parent_product_id IS NULL`)을 기존 순서대로 놓고, 각 본품 뒤에 그 본품을 가리키는 애드온을 `id` 순으로 붙인다. 어느 본품에도 매칭되지 않는 애드온(본품이 취소·삭제된 예외 상황)은 목록 끝에 일반 항목으로 놓는다.

## 주문 엑셀 내보내기

현재 엑셀은 주문 1건이 1행이고 `상품명` 칸에 `상품A x2, 상품B x1` 처럼 합쳐 넣는다. 이 칸에 묶음을 드러낸다.

- 본품은 지금처럼 `{상품명} x{수량}`.
- 애드온은 바로 뒤에 `+ {상품명} x{수량}` 으로 붙인다.
- 예: `Patient Plate x1, + Gender x2, 다른상품 x1`

행 구조와 컬럼 구성은 바꾸지 않는다. 기존 열 순서(`주문번호 … 상품명 … 상태`)에 의존하는 테스트와 운영 양식을 깨지 않기 위해서다.

모두 `tests/unit/` 에 두고 기존 관례(`CIUnitTestCase` + `DatabaseTestTrait`, `$DBGroup = 'tests'`, `tearDown` 수동 정리)를 따른다.

| `CartAddBundleTest` | 본품+애드온 한 번에 담기, 등록되지 않은 쌍 거부, 품절 애드온 거부, 재고 초과 시 재고까지만, 본품 무효 시 전체 거부 |
| `CartAddonGroupingTest` | `parent_product_id` 저장, 같은 상품 재담기 시 `COALESCE` 로 첫 분류 유지, 비회원 세션 병렬 맵 → 로그인 병합 |
| `OrderAddonGroupingTest` | 주문 생성 시 `parent_product_id` 승계, 회원·관리자 주문 상세에서 본품 아래 묶여 렌더 |
| `OrderExcelAddonTest` | 엑셀 상품명 칸에 `+ {애드온}` 이 본품 바로 뒤에 붙는지 |

품질 게이트는 저장소 규칙대로 `composer check`(PHP-CS-Fixer + PHPStan 레벨 5 + PHPUnit) 전량 통과를 기준으로 한다.

## 한계와 결정 근거

**`parent_product_id` 는 상품 id 를 가리킨다.** 한 주문에 같은 본품이 옵션만 다르게 두 줄로 들어가면 애드온은 그중 첫 줄 아래로 묶인다. 주문 항목 id 로 연결하면 정확해지지만, 장바구니 `upsert` 가 `UNIQUE (user_id, product_id, sku_id)` 로 행을 병합하므로 항목 단위 연결은 담는 시점부터 성립하지 않는다. 정확한 줄 단위 연결이 필요해지면 장바구니 병합 규칙부터 바꿔야 하며, 그것은 이 작업과 분리된 변경이다. 포장 목적에는 "어느 본품에 딸린 부속인가"만 알면 충분하다고 판단해 상품 단위로 둔다.

**애드온 재고 부족 시 담기를 막지 않고 재고까지만 담는다.** 기존 `/cart/add` 가 이미 그렇게 동작하므로 같은 규칙을 유지한다. 다른 규칙을 섞으면 같은 장바구니 안에서 항목마다 동작이 달라진다.

## 마이그레이션

새 마이그레이션 1개로 `product_addons` 생성과 두 컬럼 추가를 함께 처리한다. `down()` 에서 역순으로 되돌린다. 이 변경은 **배포 시 마이그레이션 실행이 필요하다** — `dev → main` 배포 PR 을 올릴 때 `run_migration = true` 로 워크플로를 돌려야 한다.
