# 장바구니 진입 시 상품 자동 선택 — 설계

## 배경

`app/Views/shop/cart.php`는 서버가 선택 상태를 전달하지 않고, 뷰의 체크박스에도 `checked` 속성이 없으며, 인라인 스크립트도 로드 시점에 요약(선택 개수/합계)을 갱신하지 않는다. 그 결과 장바구니 진입 시 모든 상품이 선택 해제된 상태로 표시되고, 사용자는 결제하려면 매번 "전체 선택"을 눌러야 한다.

## 목표

장바구니 페이지 진입 시 **구매 가능한(품절이 아닌) 상품은 모두 선택된 상태**로 시작하도록 한다. 품절 상품은 체크박스가 `disabled`이므로 선택 대상에서 제외한다.

## 변경 범위

파일 1개, `app/Views/shop/cart.php`만 수정. 서버(컨트롤러/모델/DB) 변경 없음 — 선택 상태는 여전히 영속화하지 않으며(기존 정책 유지: 장바구니 재진입 시 이전 선택은 흘려보낸다), 페이지 렌더링 시점의 초기 체크 상태만 바꾼다.

1. **개별 상품 체크박스**: `$isSoldOut`이 아니면 `checked` 속성을 함께 출력.
2. **전체선택 체크박스**: 품절이 아닌 상품이 1개 이상 있으면 페이지 로드 시 `checked`로 출력(개별 항목이 모두 선택된 초기 상태와 시각적으로 일치시킴).
3. **인라인 스크립트**: 페이지 로드 직후 `updateSummary()`를 1회 호출해, 초기에 이미 체크된 상품 수/합계가 요약 영역과 결제 버튼 활성화 상태에 반영되도록 한다. (현재는 로드 시 호출이 없어 체크박스는 선택돼 있어도 요약이 하드코딩된 "0개/0원"으로 남아 결제 버튼이 계속 비활성 상태가 되는 문제가 있어, 이 스텝이 없으면 수정의 의미가 없다.)

## 테스트

뷰/JS 단의 국소적 UI 초기 상태 변경으로, 이 저장소의 PHPUnit 스위트(Service/Model 중심)로는 검증되지 않는다. 브라우저에서 수동으로 다음을 확인한다:
- 장바구니에 상품이 있을 때 진입 시 모든 상품이 체크되어 있고 요약/결제 버튼이 즉시 올바른 값으로 활성화되는지.
- 품절 상품이 섞여 있을 때 품절 상품만 미선택 상태로 남는지, 전체선택 체크박스가 품절 상품 유무에 따라 올바르게 표시되는지.
- 개별 체크 해제/전체선택 토글이 기존처럼 정상 동작하는지(회귀 확인).
